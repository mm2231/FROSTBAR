# ADR-0001: Hybrid project layout

Status: accepted (2026-10-28)

## Context

The domain logic must be testable with `swift test`, without Xcode and without
code signing. SwiftPM cannot produce a signed `.app` bundle or install a launchd
daemon, while an Xcode-only project would drag AppKit into every unit test.

## Decision

- A local SwiftPM package `FrostBar` provides four library products:
  `FrostBarCore`, `FrostBarModes`, `FrostBarProfiles`, `FrostBarSMC`, plus the
  vendored `SMCKit` target and four test targets.
- `FrostBar.xcodeproj` contains exactly two targets: `FrostBar` (app) and
  `FrostBarHelper` (command-line tool embedded in the app bundle).
- All adapters that need Apple frameworks (XPC, `NSWorkspace`, `SMAppService`,
  Sparkle, SwiftUI) live in the app target.
- Orchestration (`ControlLoop`) lives in `FrostBarModes` so it is covered by
  `swift test`.

## Consequences

- CI runs `swift test` on every push and `xcodebuild build CODE_SIGNING_ALLOWED=NO`
  as a compile check for the two targets.
- Adding a new layer means adding a product to `Package.swift`; adding UI means
  touching only `App/`.
- The Xcode project is generated by `scripts/gen_xcodeproj.py` to keep the
  file list in sync with the filesystem.
